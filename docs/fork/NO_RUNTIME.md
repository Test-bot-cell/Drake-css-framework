# Attentes sans runtime par composant

## Statut

Ce document consigne, composant par composant, ce que livre le HTML initial lorsque le
runtime TypeScript ne s'exécute pas, et le repli natif qu'une intégration conforme
**DOIT** prévoir pour toute action essentielle (docs/fork/MOBILE_FIRST_SEO.md §2).

Le pendant machine de ce contrat est vérifié par le gate G7 : les attentes chiffrées du
catalogue, JavaScript désactivé (titres, liens avec `href`, texte, alternatives, contrôles
natifs), sont committées dans `tests/fixtures/compat/no-runtime.json` et comparées à
chaque exécution de `pnpm check-compat`.

Deux composants n'existent pas dans le HTML initial (`lightboxPanel`, `notification` :
générés par le runtime) : leur contenu ne doit donc jamais être essentiel. Le seul
composant dont le contenu initial est invisible sans runtime est `slideshow` — une
intégration conforme n'y place pas de contenu primaire sans alternative.

## Composants du noyau

| Composant               | HTML initial sans runtime                                                                                                                                                                              | Repli natif recommandé                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| drk-accordion           | Tout le contenu des items est présent et visible (le CSS ne masque pas `.drk-accordion-content`, c'est le runtime qui pose `hidden`) ; les titres `.drk-accordion-title` sont inertes                  | Laisser tout déplié (comportement par défaut sain) ou `details`/`summary` natifs si un repli est requis                          |
| drk-alert               | Message visible d'emblée ; le bouton `.drk-alert-close` est sans effet                                                                                                                                 | Aucun requis : l'alerte reste lisible ; la fermeture est une amélioration non essentielle                                        |
| drk-cover               | `img`/`video` couvrent leur conteneur via le CSS `[drk-cover]` (object-fit: cover) ; `iframe`/`canvas`/`svg` sont centrés mais non redimensionnés                                                      | Privilégier `img`/`video` avec `width`/`height` HTML : la couverture est alors 100 % CSS                                         |
| drk-drop (drk-dropdown) | Panneau visible en bloc statique dans le flux (la classe masquante `drk-drop` n'est ajoutée que par le runtime) ; liens internes utilisables ; pas de positionnement flottant ni d'ouverture/fermeture | Tous les liens du panneau en `<a href>` réels ; `details`/`summary` natifs si un repli est requis                                |
| drk-dropnav             | Liens de premier niveau `<a href>` fonctionnels ; sous-menus `.drk-dropdown` affichés dépliés dans le flux, liens utilisables                                                                          | Toutes les destinations en `<a href>` réels dans l'ordre DOM ; le survol/positionnement est une amélioration                     |
| drk-form-custom         | Le contrôle natif `select`/`input[type="file"]` superposé (opacity 0 en CSS) reste focusable, opérable et soumis par le `form` natif ; seule la façade cesse de refléter la valeur choisie             | `form` natif avec libellé initial générique sur la façade (ex. « Choisir un fichier »)                                           |
| drk-grid                | Grille et gouttières horizontales assurées par les classes CSS `.drk-grid` ; marges verticales automatiques (`drk-grid-margin`), masonry et parallaxe absentes                                         | Aucun contenu perdu ; utilitaires de marge statiques (`drk-margin-*`) si l'empilement mobile l'exige                             |
| drk-height-match        | Hauteurs non égalisées : chaque bloc garde sa hauteur naturelle, contenu intact                                                                                                                        | Aucun requis ; `min-height` CSS statique si l'alignement est critique                                                            |
| drk-height-placeholder  | Aucune `min-height` réservée : léger décalage possible sous l'élément suivi                                                                                                                            | Réserver la hauteur en CSS statique quand elle est connue                                                                        |
| drk-height-viewport     | `min-height` non calculée : la section prend la hauteur de son contenu, tout reste lisible                                                                                                             | Classe CSS statique `drk-height-viewport` (min-height 100vh)                                                                     |
| drk-icon                | L'attribut n'ajoute pas les classes : l'élément reste vide, aucune icône rendue                                                                                                                        | Classes statiques `drk-icon drk-ti drk-ti-<nom>` (masque CSS sans JS) + texte visible ou `aria-label` sur le lien/bouton porteur |
| drk-img                 | `data-src` jamais promu en `src` : l'image ne charge pas si `src` est absent                                                                                                                           | `<img src loading="lazy" width height alt>` natif (lazy-load navigateur)                                                         |
| drk-inverse             | Pas de bascule claire/sombre selon l'arrière-plan traversé ; couleurs par défaut conservées                                                                                                            | Classes statiques (`drk-light`, `drk-inverse-*`) ou fond au contraste garanti                                                    |
| drk-leader              | Texte visible et lisible ; les pointillés de conduite (générés via `data-fill` par le runtime) sont absents                                                                                            | Aucun requis : le contenu textuel est déjà livré ; séparateur CSS statique si voulu                                              |
| drk-margin              | Pas de marge verticale automatique entre éléments passés à la ligne                                                                                                                                    | Utilitaires de marge statiques (`drk-margin-*`) posés dans le HTML                                                               |
| drk-modal               | Contenu du dialogue présent dans le DOM mais invisible (`.drk-modal-dialog` opacity 0) et impossible à ouvrir                                                                                          | Aucun contenu ou action essentiels réservés au modal : page/section dédiée en `<a href>` réel, `form` natif                      |
| drk-nav                 | Menu entièrement déplié : tous les sous-`<ul>` visibles, liens `<a href>` fonctionnels ; pas de repli accordéon                                                                                        | Laisser déplié (état par défaut sain) ; le repli est une amélioration                                                            |
| drk-navbar              | Liens de la barre fonctionnels ; `.drk-navbar-dropdown` affichés dépliés dans le flux ; pas de survol ni positionnement                                                                                | Toutes les destinations en `<a href>` réels, hiérarchie lisible dans l'ordre DOM                                                 |
| drk-offcanvas           | Contenu du tiroir présent dans le DOM mais hors écran (`.drk-offcanvas-bar` en absolu à -270px), invisible ; le toggle ne l'ouvre pas                                                                  | Dupliquer la navigation essentielle en liens visibles dans le flux (`nav` native) ; le tiroir est une amélioration               |
| drk-overflow-auto       | Pas de `max-height` calculée : le contenu s'affiche en pleine hauteur et la page défile nativement                                                                                                     | Aucun requis : défilement de page natif                                                                                          |
| drk-overflow-fade       | Ni fondu ni `overflow` ajoutés (la classe `drk-overflow-fade-horizontal` vient du runtime) : le contenu large déborde du conteneur                                                                     | Classe statique `drk-overflow-auto` sur le conteneur (défilement natif contenu)                                                  |
| drk-responsive          | Média affiché, largeur bornée à 100 % par le CSS `[drk-responsive]` ; ratio non recalculé (hauteur d'attribut conservée)                                                                               | Attributs `width`/`height` HTML + `aspect-ratio` CSS statique (`img`/`video` : ratio intrinsèque natif)                          |
| drk-scroll              | Le lien ancre `<a href="#…">` fonctionne nativement (saut direct, sans défilement animé)                                                                                                               | Ancre native ; option CSS `scroll-behavior: smooth`                                                                              |
| drk-scrollspy           | Contenu visible d'emblée (l'opacity 0 initiale n'est posée que par le runtime) ; pas d'animation d'apparition                                                                                          | Aucun requis : l'apparition est une amélioration purement décorative                                                             |
| drk-scrollspy-nav       | Liens ancres natifs fonctionnels ; pas de surbrillance `.drk-active` au défilement                                                                                                                     | Ancres réelles `<a href="#…">` ; état actif statique si pertinent                                                                |
| drk-sticky              | Élément dans le flux normal, visible, il défile avec la page                                                                                                                                           | Aucun requis ; option CSS `position: sticky`                                                                                     |
| drk-svg                 | `<img src="….svg">` natif affiché (alt, dimensions) ; ni inlining, ni sélection de fragment `#id`, ni animation de trait                                                                               | `<img>` avec `src`, `alt` et dimensions ; un fichier SVG par symbole si un fragment était visé                                   |
| drk-switcher            | Seul le panneau marqué `.drk-active` est visible (CSS `.drk-switcher > :not(.drk-active)` masque les autres) ; les toggles ne commutent plus                                                           | Panneau initial marqué `.drk-active` en HTML ; contenu essentiel aussi accessible par liens réels (ancres ou pages)              |
| drk-tab                 | Identique à drk-switcher : barre d'onglets affichée, seul le panneau `.drk-active` visible, liens `href="#"` inertes                                                                                   | Ancres ou pages réelles pour chaque onglet essentiel ; premier panneau marqué `.drk-active`                                      |
| drk-toggle              | La cible n'est pas basculée ; si le toggle est `<a href="#cible">`, le saut d'ancre natif subsiste                                                                                                     | `<a href>` réel vers une cible déjà visible, ou `details`/`summary` natifs                                                       |
| drk-video               | `<video>`/`<iframe>` natifs affichés ; pas de lecture/pause pilotée (inview, hover) ni coupure de son automatique                                                                                      | Attributs natifs `controls`, `muted`, `autoplay`, `playsinline`, `preload`, `poster`                                             |

## Composants optionnels

| Composant                                      | HTML initial sans runtime                                                                                                                                                                                                                             | Repli natif recommandé                                                                                                            |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `countdown` (`drk-countdown`)                  | Les cellules `.drk-countdown-days/hours/minutes/seconds` restent vides (chiffres injectés par le runtime) ; seuls les séparateurs statiques s'affichent                                                                                               | Rendre l'échéance côté serveur : `<time datetime="…">` lisible ou chiffres pré-remplis dans les cellules                          |
| `filter` (`drk-filter`)                        | Tous les éléments de la cible restent visibles, non filtrés ni triés ; les contrôles `drk-filter-control` sont des liens inertes                                                                                                                      | Contenu complet visible par défaut ; contrôles en vrais `<a href>` vers des vues filtrées côté serveur, sinon masqués sans JS     |
| `lightbox` (`drk-lightbox`)                    | Vignettes et liens visibles ; le clic suit le `href` réel vers le média (navigation pleine page), aucune superposition ne s'ouvre                                                                                                                     | Conserver des `<a href>` réels pointant vers chaque média — la navigation navigateur reste le repli                               |
| `lightboxPanel`                                | Absent du HTML initial : le panneau (`.drk-lightbox`, `.drk-lightbox-items`, navigation) est entièrement généré par le runtime à l'ouverture                                                                                                          | Aucun contenu propre à replier ; les médias doivent rester joignables via les `<a href>` déclencheurs du `drk-lightbox`           |
| `notification`                                 | Absent du HTML initial : composant fonctionnel créé par l'API `Drake.notification()` ; sans runtime aucun message n'apparaît                                                                                                                          | Rendre les messages d'état côté serveur en blocs statiques `.drk-notification-message` avec `role="alert"`                        |
| `parallax` (`drk-parallax`)                    | Contenu entièrement visible en position statique ; aucun déplacement, filtre ni fondu au défilement                                                                                                                                                   | Aucun requis (effet décoratif) ; ne jamais conditionner la visibilité initiale à des styles posés par le runtime                  |
| `slider` (`drk-slider`)                        | Items `.drk-slider-items` en rangée flex figée ; le dépassement de `.drk-slider-container` est rogné et inaccessible ; flèches `drk-slider-item` inertes et `.drk-slider-nav` vide (générée par le runtime)                                           | Défilement natif (`overflow-x: auto` + scroll-snap) ou liste/grille statique en flux pour que tout le contenu reste atteignable   |
| `sliderParallax` (`drk-slider-parallax`)       | Aucun style appliqué (les effets réagissent aux événements du slider) ; l'élément s'affiche tel quel dans sa diapositive                                                                                                                              | Aucun requis (effet décoratif) ; la lisibilité du contenu ne doit pas dépendre des transformations JS                             |
| `slideshow` (`drk-slideshow`)                  | Contenu invisible : aucune diapositive ne porte `drk-active` (les autres sont `display:none`) et la hauteur (`aspect-ratio`) n'est posée que par le runtime, donc `.drk-slideshow-items` a une hauteur nulle ; navigation `drk-slideshow-item` inerte | Poser `drk-active` sur la première diapositive et une hauteur/`aspect-ratio` en CSS, ou fournir le contenu aussi en flux statique |
| `slideshowParallax` (`drk-slideshow-parallax`) | Alias de `sliderParallax` : aucun style appliqué ; le contenu reste toutefois masqué avec sa diapositive tant que le repli du `drk-slideshow` n'est pas assuré                                                                                        | Aucun requis propre (décoratif) ; dépend du repli du `drk-slideshow` pour la visibilité du contenu                                |
| `sortable` (`drk-sortable`)                    | La liste s'affiche complète dans l'ordre du DOM ; aucun glisser-déposer ni réordonnancement possible                                                                                                                                                  | Ordre canonique rendu côté serveur ; si le réordonnancement est essentiel, le proposer via un formulaire natif (POST)             |
| `tooltip` (`drk-tooltip`)                      | Aucune infobulle au survol ou au focus ; le texte porté par l'attribut `drk-tooltip` est inaccessible                                                                                                                                                 | Doubler l'information par un `title` natif, un texte visible ou `aria-label` — jamais d'information exclusive au tooltip          |
| `upload`                                       | La zone (`<input type="file">`, souvent avec `drk-form-custom`) permet la sélection native de fichiers mais rien n'est envoyé : ni XHR, ni glisser-déposer (`drk-dragover`), ni progression                                                           | `<form method="post" enctype="multipart/form-data" action="…">` natif avec bouton d'envoi soumettant les fichiers                 |
